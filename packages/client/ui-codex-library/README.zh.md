# @deepseek-ai/dsh-client-ui-codex-library

[English](README.md) | 中文

## 概述

现有 Codex 与 Axiom 对话作为常规 Harness 会话出现在工作区侧边栏。行内及会话标题的来源标记标识原始执行来源。**原生对话** 页面仅管理连接，不再提供独立历史浏览器。

## 使用

将此 UI 与[原生对话服务](../../experimental/native-conversations/README.zh.md)、标准会话与工作区服务及资源注册表一起挂载。打开 **原生对话** 可读取连接状态、手动同步 Codex 对话、选择原始 ChatGPT Dot，无需输入网址，或打开桌面桥接的 ChatGPT 登录界面。刷新会重新读取状态；操作会显示失败原因，并在完成前禁用冲突操作。成功连接 Axiom 后会打开对应的常规会话。

**设置 → 常规**中的**启用 Dot 集成**与**在侧边栏显示 Dot**是分别保存的独立选项。集成默认启用，侧边栏显示默认关闭。两项均启用且桌面伴随功能与原生对话插件可用时，**Dot**会紧接**新会话**显示，未登录时也会显示。选择它会打开原始 ChatGPT 网站以登录或选择 Dot。只有此次明确选择才可将准备就绪的 Dot 作为常规会话打开；后续后台网站更新不会夺取焦点。禁用集成或卸载插件会取消等待中的导航。

工作 Codex 账户未登录时，选择**登录工作 Codex**，然后选择**在浏览器中继续**。Codex 负责本地回调和凭据存储。面板确认账户后才显示成功；**取消 Codex 登录**只取消当前等待中的尝试。不会替换已登录的账户。此登录不会认证 Axiom 使用的独立 ChatGPT 网站会话。

从工作区分组直接打开对话。标准会话渲染、输入、流式输出、工具卡片和审批展示仍由现有组件负责。Host 服务负责原始对话身份、历史加载、执行和审批路由。来源标记读取 `nativeConversation` 投影，侧边栏标记不会激活所列会话。Codex 保留模型和权限控件；Axiom 的相关设置由原始 ChatGPT 应用负责。

在提供伴随扩展的桌面构建中，**Axiom 登录连接**只读取保存的模式，不进行更改。应用使用已认证的 ChatGPT 网站会话；**使用常规浏览器**提供可选的扩展后备连接。已有的连接模式选择会保留。浏览器模式显示本地扩展文件夹、注册脚本、随附 Node 路径及请求的三项权限，供手动设置；面板不执行安装。登录与 Cookie 保留在所选浏览器配置中。打开 Dot 后，点击扩展工具栏按钮并批准原生配对提示；重新加载页面或完成新的登录后需再次配对。构建不提供伴随扩展时，保留保存的模式并说明限制。安装步骤和来源窗口限制参见[浏览器桥接参考](../../../docs/fork-release/axiom-browser-bridge.zh.md)。

账户已登录时，选择 **新聊天使用工作 Codex**，将其订阅设为后续聊天的默认选择。面板会确认已保存的选择；打开此页面不会更改默认值或替换账户。

<a id="model-experience"></a>
## 模型体验

无，因为此客户端 UI 不添加模型可见的提示词或工具。

#### KV Cache 影响

来源标记和连接状态不进入模型上下文。

## 已知限制与后续工作

<a id="known-limitations-and-deferred-work"></a>

- 连接状态按需刷新；等待中的 Codex 登录也会轮询完成状态。连接状态不能证明某轮对话或审批已完成，实际结果由会话显示。
- Axiom 连接与登录需要可用的桌面桥接。本 UI 不复制凭据，也不模拟 Dot 人设。
