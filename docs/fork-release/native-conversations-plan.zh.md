# 原生会话集成

[English](native-conversations-plan.md) | 中文

现有工作 Codex 会话以普通 Harness Session 的形式出现在所属工作区侧栏中。原始 Codex 线程仍是权威来源。打开历史不会启动轮次。发送消息通过工作 app-server 继续原始线程，并通过经过身份验证的回环 MCP 端点提供 Harness 工具。现有 Harness 审批和沙箱设置管理该端点及 Codex 原生操作。

Axiom 使用已登录的原始 ChatGPT 页面作为运行引擎。原生会话显示实际观察到的消息，并通过页面的真实输入框发送用户原文。登录保留在所选浏览器中：专用 Electron 会话，或通过可选扩展连接的日常工作浏览器。页面不受支持或发送结果不确定时明确失败，不自动重试。

导入历史时预留空的首个系统表面节点，以便后续 Harness 上下文替换该受保护的节点。导入器不会推测原始隐藏指令。压缩日志冷加载测试覆盖历史导入及真实框架上下文替换。此修复前已导入的原型镜像需要单独显式恢复，必须保留现有日志及本地工具和审批证据。

仅所有者可调用的 `nativeConversations/rebuildCodexMirror` 操作为同一原始 Codex 会话创建新的本地镜像，并归档旧镜像，不读取或改写旧正文。新记录从权威来源载入历史；本地 Harness 工具和审批证据保留在归档原件中，不复制或执行。恢复拒绝活动、置顶、已归档、种子或存在关联的 Session，并要求缓存来源身份及映射一致。发布前严格重开验证新元数据。可捕获的失败会补偿映射和导航变更；进程中断不是原子操作，重试前必须检查保留的候选、来源映射和归档状态。先备份确切受影响的日志及元数据。已安装应用中的恢复验收仍待完成。

实施与验收：

1. 持久化来源绑定，将原始消息载入普通 Session，重新打开时不重复导入。
2. 流式呈现本客户端拥有的 Codex 轮次，转发审批，映射权限和模型，提供已准备好的 Harness 工具且不重复执行。不得中断其他客户端的轮次。
3. 将 Axiom 的原生 Session 连接到桌面页面桥接，保留原始身份，说明已呈现历史的边界，并在需要时提供登录入口。
4. 运行传输、历史载入、流式输出、审批及桌面桥接的针对性测试。在专用测试线程中验证真实 Codex 续聊和 Harness 工具执行。在已安装 Mac 应用中验证 Axiom 原始历史与交互。
5. 本地重新构建并安装，重启后检查来源去重，保留工作登录与遥测默认设置，审阅差异并在本地提交。不推送或创建 PR。

运行时验收通过前目标保持进行中。启动链接、只读记录或尚未实际使用的工具均不满足验收。
