# 原生会话集成

[English](native-conversations-plan.md) | 中文

现有工作 Codex 会话以普通 Harness Session 的形式出现在所属工作区侧栏中。原始 Codex 线程仍是权威来源。打开历史不会启动轮次。发送消息通过工作 app-server 继续原始线程，并通过经过身份验证的回环 MCP 端点提供 Harness 工具。现有 Harness 审批和沙箱设置管理该端点及 Codex 原生操作。

Axiom 使用已登录的原始 ChatGPT 页面作为运行引擎。专用连续视图按来源顺序显示实际观察到的消息，并通过页面的真实输入框发送用户原文。它不创建 Harness Session 或模型轮次。旧历史滚动使用原始消息 ID 和独立隐藏历史页面。登录保留在所选浏览器中：专用 Electron 会话，或通过可选扩展连接的日常工作浏览器。页面不受支持或发送结果不确定时明确失败，不自动重试。

Dot 在新建 Session 的正下方有专用操作入口，同时受通用设置中的独立偏好和已安装集成控制。它显示选定名称（如 Axiom），是唯一对话入口。旧 Dot 镜像不再出现在普通会话列表、搜索或选择器中，日志仍保留；保存的导航转到专用视图。工作 Codex 保持普通 Session 行为。应用内网站登录是主要流程，浏览器伴随扩展为可选方式。该操作发现所选原始 Dot，不要求输入网址。认证窗口需要可用的输入、可见的重新加载与关闭控件、关闭时实际销毁页面，以及再次显式打开时保留网站登录。选择成功后仅一次返回原生对话；显式打开原始网站时保持其可见。

完成已安装应用的运行时验收后，分支更名为 Sabi，同时保留配置及现有工作登录。发布工作包括基于已有引擎的 `sabi` CLI、一致的分支版本、隐私与功能文档、迁移到 `sabino-software/sabi`，以及独立于上游签名基础设施且通过验证的 GitHub Actions 构建产物流程。不创建 PR；外部发布工作须先通过运行时验收。

导入历史时预留空的首个系统表面节点，以便后续 Harness 上下文替换该受保护的节点。导入器不会推测原始隐藏指令。压缩日志冷加载测试覆盖历史导入及真实框架上下文替换。此修复前已导入的原型镜像需要单独显式恢复，必须保留现有日志及本地工具和审批证据。

Codex 的 `input` 仅包含已接纳的人工文本和图片。新归属文本通过 `additionalContext` 作为非可信数据传递，可信 Harness 策略使用应用上下文。自包含片段在服务器每项限制内保留完整 JSON，并显式记录分组、版本和顺序。仅上下文唤醒使用原生工具输出轮次。带归属的图片上下文在发送前拒绝，人工图片仍受支持。用户原文中的 JSON 不变。实时连续轮次验证了同一已订阅原始线程上的上下文和策略更新；仅上下文验证仅产生一个模型轮次，没有添加人工消息。

仅所有者可调用的 `nativeConversations/rebuildCodexMirror` 操作为同一原始 Codex 会话创建新的本地镜像，并归档旧镜像，不读取或改写旧正文。新记录从权威来源载入历史；本地 Harness 工具和审批证据保留在归档原件中，不复制或执行。恢复拒绝活动、置顶、已归档、种子或存在关联的 Session，并要求缓存来源身份及映射一致。发布前严格重开验证新元数据。可捕获的失败会补偿映射和导航变更；进程中断不是原子操作，重试前必须检查保留的候选、来源映射和归档状态。先备份确切受影响的日志及元数据。

已安装应用检查重建了两个受影响的原型镜像，两个原始日志的哈希均未改变，原始 Codex ID 均保留。真实历史会话在原生渲染器中打开，没有启动推理。受控导入历史在应用重启后成功重开。侧栏同步未重复导入任何会话。通过已安装界面新建的聊天使用工作 Codex，返回预期回复，并在重启后重开。运行时清单显示五个 Harness 上报插件均已禁用且未挂载；现有工作凭据文件的字节内容保持不变。Axiom 原始历史与交互仍需完成已登录状态下的实时验收。

已安装的上下文修复在现有干净 Codex 会话中继续对话，执行了一次命令恰为 `pwd` 的 `skeinlet/bash` 调用，并保存一条逐字节一致、没有框架 JSON 的人工消息。权威来源回读确认原始线程 ID 及已完成的工具结果。应用完整重启后，八轮原生历史成功重开，没有历史错误或框架 JSON 原文。另六个本地测试镜像已归档，其原始 Codex 来源不变，保留一个具名验收聊天供查看。

实施与验收：

1. 持久化 Codex 来源绑定，将原始消息载入普通 Session，重新打开时不重复导入。
2. 流式呈现本客户端拥有的 Codex 轮次，转发审批，映射权限和模型，提供已准备好的 Harness 工具且不重复执行。不得中断其他客户端的轮次。
3. 将 Dot 专用视图直接连接到桌面页面桥接，保留原始身份、来源顺序和网站主题。在不影响实时来源的情况下加载旧历史，并在需要时提供登录入口。
4. 运行传输、历史载入、流式输出、审批及桌面桥接的针对性测试。在专用测试线程中验证真实 Codex 续聊和 Harness 工具执行。在已安装 Mac 应用中验证 Axiom 原始历史与交互。
5. 本地重新构建并安装，重启后检查来源去重，保留工作登录与遥测默认设置，审阅差异并在本地提交。不推送或创建 PR。

运行时验收通过前目标保持进行中。启动链接、只读记录或尚未实际使用的工具均不满足验收。
