# Native conversation integration

English | [中文](native-conversations-plan.zh.md)

Existing work Codex conversations become ordinary Harness Sessions in their workspace sidebar. Their original Codex thread remains authoritative. Opening history does not start a turn. Sending continues that thread through the work app-server, with scoped Harness tools provided through an authenticated loopback MCP endpoint. Existing Harness approvals and sandbox selections govern that endpoint and native Codex operations.

Axiom uses the original authenticated ChatGPT page as its engine. A dedicated continuous view displays observed original messages in source order and sends exact user-authored input through that page's real composer. It creates no Harness Session or model turn. Older-history requests use original message IDs, read already-loaded original rows first, and use a separate hidden page when more content must load. Sign-in stays in the selected browser: either the dedicated Electron session or the optional companion in the regular work browser. Unsupported page states and ambiguous sends fail explicitly without retrying.

Dot has a dedicated action directly below New Session, gated by independent General Settings preferences and the installed integration. It displays the selected name, such as Axiom, and is the only conversation entry. Legacy Dot mirrors are hidden from ordinary session lists, search, and pickers while their logs are preserved; saved navigation is consumed without opening Dot. Only the top button opens its conversation. Work Codex stays in ordinary Sessions. In-app website sign-in is the primary flow; the browser companion is optional. The action discovers the selected original Dot without asking for its URL. Authentication windows need working input, visible Reload and Close controls, actual page destruction on Close, and explicit reopening without losing the website login. Successful selection returns to the native conversation once; opening the original website explicitly keeps it visible.

Sabi preserves its profile and existing work login. The `sabi` CLI uses the existing engine; the fork build version is `0.3.0-beta.1`. Transfer to `sabino-software/sabi` remains gated on runtime acceptance and authorization. The independent artifact workflow is configured; hosted CI acceptance awaits an actual run. No PR is requested.

Imported histories reserve an empty first system surface so later Harness context can replace that protected head. The importer does not infer original hidden instructions. Compressed cold-load tests cover both import and a real framework context replacement. Prototype mirrors hydrated before this fix need separate explicit recovery; their existing logs and local tool or approval evidence must be preserved.

Codex `input` contains admitted human text and images. Fresh attributed text uses `additionalContext` as untrusted data; trusted Harness policy uses application context. Self-contained fragments preserve complete JSON within the server's per-entry limit, with explicit group, revision and order. Context-only wakes use native tool-output turns. Attributed image context is refused before sending; human images remain supported. Literal human JSON is unchanged. Live consecutive-turn probes verified context and policy updates on the same subscribed original thread, and a context-only probe verified one model turn with no added human message.

The owner-only `nativeConversations/rebuildCodexMirror` operation creates a new local mirror of the same original Codex chat and archives the old local mirror without reading or rewriting its body. Its new transcript hydrates canonical source history; local Harness tool and approval evidence stays in the archived original and is not copied or executed. Recovery refuses active, pinned, archived, seeded or related Sessions and requires matching cached source identity and assignment. Strict reopening validates the new metadata before publication. Caught failures compensate index and navigation changes; a process interruption is not atomic and requires inspecting the retained candidate, source assignment and archive state before retrying. Back up the exact affected logs and metadata first.

Implementation and acceptance:

1. Persist Codex source bindings and hydrate original messages into ordinary Sessions without duplicating source messages on reopen.
2. Stream owned Codex turns, route approvals, map permissions and models, and expose prepared Harness tools without double execution. Never interrupt another client's turn.
3. Connect the dedicated Dot view directly to the owned desktop page bridge; retain original identity, source chronology and website-inspired styling. Load preceding history without disturbing the live source and provide sign-in only when required.
4. Run focused transport, hydration, stream, approval, and desktop bridge tests. Verify real Codex continuation and a real Harness tool in a designated test thread. Verify original Axiom history and interaction in the installed Mac app.
5. Rebuild and install locally, check source deduplication after restart, preserve the work grant and telemetry defaults, inspect the diff, and commit locally. No push or PR.

The goal stays active until these runtime checks pass. A launcher, a read-only transcript, or configured-but-unused tools do not meet acceptance.
