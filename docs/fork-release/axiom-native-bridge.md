# Original Dot page adapter

English | [中文](axiom-native-bridge.zh.md)

Sabi's optional Dot integration displays the original `https://chatgpt.com/dots/<id>` conversation in a dedicated continuous view, reached only through its top sidebar button. It creates no Harness Session or model turn. The original ChatGPT website owns the engine, messages, authentication, and submission rules. The adapter does not replace the Dot with another model request, copy browser cookies, read token storage, or call private ChatGPT APIs.

## Selection and sign-in

In **Settings → General**, **Enable Dot integration** and **Show Dot in sidebar** are independent saved preferences. The integration defaults to enabled and sidebar visibility to off. **Dot button style** offers **Match New Session** (the default), **Subtle**, and **Outline**, all sharing New Session geometry. With both enabled and the installed native integration available, the selected Dot's name, such as **Axiom**, appears directly below **New Session**; an unselected connection uses **Dot**. No URL input is required. The button opens the dedicated view and selects the original website when needed. Settings configure the connection without opening a conversation. Background website updates never navigate the workspace. Integration disablement and plugin disposal cancel pending selection.

Old Dot mirror logs are preserved, but hidden from ordinary session lists, search, and session pickers. Saved navigation and direct legacy links are consumed without opening Dot or retaining its old session. Only the top button opens the Dot conversation. Work Codex chats retain ordinary Session behavior.

The primary connection uses a dedicated persistent Electron website session. Sign-in takes place on the real ChatGPT and admitted identity-provider pages; Codex sign-in does not authenticate this website session. The [regular-browser companion](axiom-browser-bridge.md) is an optional fallback that keeps login in the selected browser profile. Opening the connection panel preserves the saved transport preference. After connecting, the original page runs hidden to power native history, sends, and replies. **Open ChatGPT** reveals it for direct interactions; **Reload page** refreshes it. **Close page** destroys the page and child popups and stops observation. Background observation cannot reopen it; another explicit Dot selection reconnects using the retained website session. No browser extension or DeepSeek account is required for this in-app connection.

## Native content and sending

Only original user and assistant `.message-text` bodies are projected, preserving original IDs, source order, roles, timestamps, and supported Markdown. Each row is read independently; autonomous Dot updates are not grouped into artificial alternating turns. Nested quoted messages do not become extra timeline events. Actions, body-external quoted replies, scripts, hidden nodes, and automatic image loading are excluded. The dedicated theme follows the original page's dark canvas, purple user bubbles, muted assistant bubbles, and conversation spacing.

The latest snapshot is bounded to 100 messages. Scrolling upward requests preceding pages by exact source ID, without imposing a total conversation-message ceiling. Preceding messages already loaded in the original page are read first. When none are loaded, a separate lazy hidden history page uses the same retained website session to scroll for more, leaving the live page's composer untouched. Older-history behavior still awaits installed-artifact acceptance. Older content must actually load on the original page before it can appear natively. The adapter never infers the beginning of history from a timeout or an empty result: without a verified source boundary, it reports retryable unavailability and retains the possibility of older history. The optional browser companion does not provide older-history pagination. Website status is shown as observed. A typing indicator alone does not establish activity.

Sending requires explicit native user input. The adapter refuses to overwrite a nonempty original draft, inserts the exact text through the selected transport, verifies it, and clicks the real enabled Send control. ChatGPT decides whether a submission can queue while the Dot works. Confirmation requires a new original user-message ID with matching text. Ambiguous submissions are reported without automatic retry; process-local request IDs suppress duplicate clicks. DOM changes can make the adapter unavailable; they never justify synthetic source content.

## Navigation and verification

Bound conversation navigation admits the selected Dot, ChatGPT authentication routes, and OpenAI's authorization issuer. An explicitly revealed authentication flow also admits the configured Google, Apple, and Microsoft identity origins. The visible chooser allows ChatGPT selection pages while unbound; unrelated origins and browser schemes remain blocked. Authentication query fields and credentials are excluded from native snapshots. Fork reporting is disabled by default, but the original website and identity providers retain their own telemetry and network behavior.

Installed-core checks confirmed persistent in-app authentication, one native send and the observed original reply, signed-in reload, hidden-page interaction, and explicit close/reopen without another login. These checks exercise the real website rather than only fixtures or the optional browser companion. Installed package 22 verified a native Dot send and original Codex continuation. Repeat the native send/reply, Reload, Close, and explicit reconnection checks against the final-source artifact. Final-source artifact and older-history acceptance remain pending; local checks do not establish hosted CI acceptance. The [release verification procedure](plan.md) records that boundary.
